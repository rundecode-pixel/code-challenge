# T09 — Deployment, observability, load test

**Epic**: Problem 6 — Live scoreboard
**Depends on**: T01–T08
**Delivers**: the feature runnable and measurable in a realistic environment.

## Context

T01–T08 build the system; this ticket proves it survives real conditions:
operational config, period resets, observability for the adversarial edge
cases, and a load test against the NFR targets from `../docs/DESIGN.md` §1.

## Tasks

1. **docker-compose for the full stack**:
   - Postgres 16 (persistent volume) + Redis 7 (with ACL user limited to the
     commands the app uses; no default-user access from the network).
   - API server, SSE pool (scale=2), rebuild worker.
   - Healthchecks: `GET /healthz` for API/SSE, `redis-cli ping` /
     `pg_isready` for stores.
2. **Env + secrets**: `.env.example` documenting every variable
   (`JWT_PROOF_SECRET`, `DATABASE_URL`, `REDIS_URL`, `SSE_HISTORY_TTL`, …);
   secrets never in compose — only referenced from env.
3. **Period resets** — cron/worker job:
   - Daily 00:00 UTC: reset `daily_score`, rotate `leaderboard:daily`.
   - Weekly Monday 00:00 UTC: reset `weekly_score`, rotate
     `leaderboard:weekly`.
   - `all_time` never resets. Rotation = RENAME old key → archive, rebuild new
     key from `score_events` (reuses T03 rebuild).
4. **Observability**:
   - Structured JSON logs on every `complete` (decision point):
     `actionId, userId, outcome (credited|replay|invalid|retriable), points, latency_ms`.
   - Metrics: `score_events_total{outcome}`, `sse_connections`,
     `leaderboard_delta_propagation_ms` (histogram),
     `zset_rebuild_duration_ms`.
   - Alert rules: replay-rate spike (> 1% of completes — someone is probing),
     ZSET drift detected, SSE pool connection churn.
5. **Load test** (k6 or artillery, committed as a script):
   - Ramp to 10k concurrent SSE clients.
   - Sustain 1k `complete`/s peak for 10 min.
   - Assert: p95 `complete` < 100 ms; p95 delta propagation < 500 ms; zero
     double-credit observed (sum of credited points == ZSET total at the
     end); SSE pool RSS flat after warm-up (no leak).
6. **Runbook stub**: `docs/runbook.md` — how to trigger a ZSET rebuild, what
   `503 LEADERBOARD_UNAVAILABLE` means, reconciliation procedure when
   Postgres and Redis diverge.

## Acceptance criteria

- [x] `docker compose up` boots the full stack; healthchecks green.
- [x] Period reset job correctly rotates daily/weekly keys and rebuilds from
      Postgres (integration).
- [x] Logs/metrics/alerts exist for every decision point and failure mode in
      the threat model; one grep line explains any outcome.
- [x] Load test passes the NFR numbers above with no double credits; results
      recorded in `docs/load-test-report.md`.
- [x] Runbook covers ZSET rebuild + reconciliation.
- [x] `npm run typecheck` clean across the whole workspace.
