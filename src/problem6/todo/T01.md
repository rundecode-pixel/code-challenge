# T01 — Postgres schema + migrations

**Epic**: Problem 6 — Live scoreboard
**Depends on**: nothing
**Delivers**: the source-of-truth data layer for scores.

## Context

Postgres is the authoritative store for scores. Every credit that survives the
anti-cheat gate ends up here as an immutable `score_events` row plus an upsert
into `scores`. Redis projections (T03) are rebuildable from this data, so this
schema must be correct and complete first.

## Tasks

1. Create the migration for the two tables below (match the existing project's
   migration conventions — hand-written TypeORM migrations under
   `src/problem5/migrations/` named `<timestamp>-<Name>.ts`, applied via
   `npm run p5:db:migrate`).
2. Define the `score_events` table:
   - `action_id UUID PK` — server-generated; doubles as the anti-replay guard
     (settlement key). The primary key *is* the one-shot guard: a duplicate
     insert can never succeed.
   - `user_id UUID NOT NULL REFERENCES users(id)`
   - `action_type TEXT NOT NULL` — validated against the scoring registry
     (T02) before insertion.
   - `points INTEGER NOT NULL CHECK (points > 0)` — server-computed, never
     client-supplied.
   - `metadata JSONB NOT NULL DEFAULT '{}'` — original action payload for audit.
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
   - Index `(user_id, created_at)` for per-user history queries.
3. Define the `scores` table:
   - `user_id UUID PK REFERENCES users(id)`
   - `total_score INTEGER NOT NULL DEFAULT 0` (all-time)
   - `daily_score INTEGER NOT NULL DEFAULT 0`
   - `weekly_score INTEGER NOT NULL DEFAULT 0`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
4. Create `score_events` and `scores` **inside one transaction** with the
   `complete` credit write, so the ledger row and the projection update are
   atomic (implemented in T04; the migration only creates the tables here).
5. Add a migration helper: `createUserScoresIfMissing(userId)` used by the
   credit path when a user has no `scores` row yet.

## Acceptance criteria

- [x] `npm run typecheck` passes (new TypeORM entities typed, no `any`).
- [x] `migrate dev` applies cleanly to an empty database and is repeatable.
- [x] A fresh `score_events` row for a user without a `scores` row works (the
      helper creates it).
- [x] DB-level `CHECK (points > 0)` rejects non-positive points even if app
      code regresses.

## Out of scope

- Redis (T03), token issuance (T02), credit write path (T04).
- Resetting `daily_score`/`weekly_score` (cron in T09).
